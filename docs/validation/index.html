Octaryn Validation

Proof before polish.

Validation is owner-scoped. Use focused targets for the area changed, then aggregate validation for broad documentation, build, API, or runtime work.

Quick Start

tools/build/cmake_configure.sh debug-linux
tools/build/cmake_build.sh debug-linux --target octaryn_validate_all
tools/build/cmake_build.sh debug-linux --target octaryn_validate_owner_launch_probes
tools/build/cmake_build.sh debug-linux --target octaryn_validate_client_app_launch_probe

Runtime Proof

Clean builds are not enough for streaming, scheduling, rendering, persistence, or authority changes. Capture direct runtime evidence that exercises the real path.

  • Client chunk streaming remains bounded across multiple server-seed mesh batches.
  • Mesh CPU work routes through native jobs while GPU calls stay on the client main thread.
  • Indirect draw remains stable and render-distance far plane keeps radius-32 terrain visible.
  • Server stream logs avoid recurring metadata-only JSON churn.
  • Persistence writes authoritative edits and metadata, not generated seed terrain blocks.
