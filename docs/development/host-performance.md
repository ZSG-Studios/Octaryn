# Host performance implementation and qualification

The production session path uses typed in-memory command/pose exchange inside
the client and the existing LiteNetLib/LiteEntitySystem transport between client
and server. Singleplayer launches a separate authoritative server on an ephemeral
loopback port. A startup endpoint file and a shutdown request remain lifecycle
signals; command, pose, action and module-event JSON files are no longer production
mailboxes. Low-rate window/time/action payloads still use JSON on the wire.

Commands retain the complete unacknowledged prefix (64 commands per transport
batch; 128 in prediction history). Action journals retain unacknowledged actions,
admit bounded prefixes and acknowledge only admitted sequences. The status read
uses an immutable published snapshot. Transport initialization completes before
the process-wide client pointer is published, preventing an initial window intent
from being accepted and then erased during startup.

Collision handles retain immutable geometry until the final prediction/startup
owner releases it. Native cached worlds are released before geometry storage.
Tile collision uses independently prepared Box3D meshes; BVHs build on asset
workers, and publication/removal runs on the owner thread. Build 10 preloads
all authority tiles before readiness. Build 11 authority residency
change replaces this with a spatial tile index and two NativeJobs preparation
slots. Every player protects its maximum accepted speed or current horizontal
velocity multiplied by clamped delta time plus two metres; each awake item
protects its velocity-expanded footprint independently of player distance. A 16 m prefetch
margin and two-second retention prevent boundary churn. Preparation is capped
at 64 MiB encoded bytes and 250,000 triangles per tile. Resident collision uses
a conservative 512 MiB reservation budget and 256-tile count limit. The
`OCTARYN_SERVER_COLLISION_BUDGET_MIB` setting accepts 64–4096 MiB. Two preparation
slots separately reserve at most 72 MiB each, so a nearly full resident budget
cannot prevent decoding a small missing tile. Publication charges its actual
decoded geometry estimate. Reservations estimate Box3D storage; they are not
measured RSS and exclude bounded decoder/source staging and descriptor metadata.

The cooked Bistro manifest has 137 tiles. Lightweight JSON-header inspection
found that the spawn's 10 m floor-search region intersects 37 tiles and reserves
364.61 MiB; a 4 m sample intersects 26 tiles and reserves 262.42 MiB.
The 512 MiB default follows that measured layout. Evidence is
`logs/server/collision-budget-bistro.json`, generated by
`tools/validation/authority_collision_budget.py`. These are accounting estimates,
not runtime residency measurements. Tiled spawn floor search uses the resident
collision scene, including ascending backface tests, and does not assume that
the first manifest GLB contains the spawn floor.

The same header audit found a 4 m region at x=-2.230,z=1.053 intersecting 62 tiles
and estimating 628.46 MiB. The 512 MiB default therefore does **not** qualify
arbitrary Bistro traversal. A separately recorded larger map budget or tighter
spatial partitioning is required there; the 33-cell fixture cannot establish
Bistro residency coverage. Tile-center samples are not a global worst-case proof.

Pending player collision pauses command selection, sequence acknowledgement,
and the command expiration clock. Pending item collision returns a successful
held state so the host cannot enter its analytic falling path. Failed tiles
remain unavailable with an explicit diagnostic. Budget pressure stalls bodies
through the eviction hysteresis; an oversized protected set then reports a
fatal budget diagnostic instead of waiting indefinitely or evicting required
collision. Sleeping items need no retained tile
until reactivated. Obsolete preparations are discarded before publication;
world destruction joins outstanding jobs before releasing collision ownership.
Initial spawn waits up to 60 seconds for its region. No readiness epoch is sent
over the network in this slice: authority and prediction each gate their own
collision. Build 11 passed the focused multi-anchor/item, cancellation, eviction,
invalid-budget and lifetime fixture at `logs/server/collision-residency-si_sttmn`.
After five warmup lifetimes, RSS range was 90,112 bytes and slope 7,548 bytes/world;
private memory range was 1,069,056 bytes and slope 103,014 bytes/world. The fixture
also confirmed explicit failure when a protected set exceeded a 64 MiB budget.
Build 12 also passed the maximum-delta diagonal-fly swept-region hold/resume
regression in `logs/server/collision-residency-u0q3ai99`. These small-world results do not qualify
general Bistro residency or a long traversal.
Client prediction rejects a proposed step into collision that is not resident.

at 60 Hz, follows authoritative positions across 33 contiguous 24 m cells, and

tile-boundary crossings, turns, source ticks, ACK progression and a real inventory
drop receipt and floor-settling diagnostic. The process monitor records working-set/private memory every second;
after a 300-second warmup, both must stay within a 64 MiB range and a positive

transport, not graphical client collision, prediction or rendering quality.

Long runs use independently copied runtime snapshots under each owner's
`build/release-windows/<owner>/qualification/<case-id>`. All server payload files
and client root runtime files have source/copy SHA256 equality recorded in
`runtime-snapshot.json`; no hardlinks are used. Client graphics assets are not
copied. This keeps normal bundle outputs available for unrelated renderer builds
without mutating a running qualification's authority or transport binaries.

## Reconnect continuity

The real reconnect fixture exposed a pre-existing reset mismatch:
`logs/server/typed-session-8n8495eo` disconnects atACK150, then the reattached
server resets its source clock while the client retains its command journal.
The fixture correctly failed on regressing authority ticks.

Protocol8 adds a random per-client-start session identifier to the versioned
hello. A matching resumed hello retains authority command/action state; a new
identifier starts a new session. The welcome echoes identity, resume status and
authority ACK before the client resumes sending. Losing previously welcomed
authority state fails visibly and requires a fresh session. This is continuity
on the existing transport, not account authentication or encrypted networking.
Non-owning peers cannot submit LES packets, and a welcomed peer cannot change
its identity in place. Client/server/shared bundle hashes matched after build15
(`logs/server/protocol8-bundle-identity.json`).

A bounded256-event authority journal retains module receipts. Client queues
survive automatic reconnect; monotonic envelopes suppress duplicate replay.
Build15 acknowledged network enqueue and rejected overflow with an exception.
Review identified that a stopped presentation consumer could therefore fill its
queue after the server had retired receipts, and a module could mutate inventory
before encountering a full outbound journal.

The subsequent source slice changes receipt ACK to native-consumer polling and
returns false on a full server journal. The existing replication API now reports
available capacity (native table version2/32 bytes). Authority action admission
and dequeue hold under pressure; a deferred action ACK keeps its intent pending.
Basegame drop/pickup checks capacity before mutation, and target publication
defers without changing its published state. Check/mutate/publish stays on the
serialized authority thread. Focused isolated builds/tests pass in
`logs/server/replication-backpressure-journal.log` and
`logs/server/replication-backpressure-items.log`; native ABI layout checks pass

All values below are focused Windows tests, not complete engine frame budgets.
The native Box3D fixture uses a two-triangle floor, no item-item contacts and
10,000 deliberately awake contact queries each sample. Three runs of 180 measured
ticks followed 20 warmup ticks. At 10,000 items the per-run medians were 12.724,

## HQ200 authority implementation and build19 evidence

Canonical `octaryn_all` passed in `logs/build/performance-build-19.log`.
Protocol9 adds versioned 64-byte item poses and an88-byte native presentation
record carrying generation, current pose/source tick and previous pose/tick.
Replication ABI3 is48bytes. `LocalSession.world_items()` returns a read-only
span valid until the next session update/stop. Item ticks use the module/world
clock, which is independent of the player's accepted input sequence.

The server bounds active items plus pending tombstones at10,000, coalesces
transform changes, and sends at most512poses per ACK-gated batch at up to20Hz.
Baselines publish atomically on the client; reconnect starts a fresh baseline.
The durable action/receipt journal remains separate and cannot coalesce.
All reliable traffic currently shares LiteNetLib's existing lane. At10,000
simultaneously moving items, the ideal zero-latency stream ceiling is about
one update per entity per second; RTT/loss further reduces freshness. This
bounded implementation does not establish HQ motion at that extreme scale.

Player saves now use a two-pending-write queue and one ordered writer. Only
actual completed writes call native `NoteSaved`; regular ticks do not wait on
disk. Lifecycle flushes wait for completion and surface storage failures.
Diagnostics use bounded asynchronous queues with explicit drop reporting;
authority receipts never use those queues. Module tick callbacks reuse their
context and delegate rather than allocate a capturing closure each tick.

Whole-listener CSVs now measure control/shutdown checks, network callbacks,
LES update, authority/session/module execution and item replication. Separate
module CSVs measure authority scheduling and module work. Values are wall time,
not CPU execution time; allocation deltas use process-wide approximate GC
counters and can include worker allocations. Profiling is opt-in through
`OCTARYN_SERVER_LOOP_PROFILE`, `OCTARYN_SERVER_MODULE_PROFILE` and the existing
`OCTARYN_SERVER_TICK_PROFILE`.
