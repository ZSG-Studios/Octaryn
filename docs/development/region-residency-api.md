# Source-owned region residency

The renderer publishes bounded prepared region payloads; a game module chooses its source policy. Generic distance defaults do not establish original-game cell attach/detach behavior.

A version1 map manifest may add `tile_ids` aligned with `tiles` and `tile_files`. IDs are unique ASCII strings of1–128 bytes; missing IDs use `tile/index` for legacy manifests. Tile bounds use the same engine-space origin as their glTF node transforms. Each payload is admitted before preparation with at most64MiB source buffers,64MiB encoded images,131072 triangles,2048 primitives,393216 elements per accessor and64MiB flattened CPU geometry. Prepared geometry/images remain subject to existing memory and fenced GPU admission.

For source-driven policy use `tile_residency:"external"` and nonempty unique in-range `tile_initial_wanted:[indices]`. Startup initially retains that set too, permitting collision readiness before module ticks begin. External mode does not derive desired or retained regions from camera distance. Camera/player distance only orders bounded work. Reference attach callbacks, original collision primitives and game buffer semantics require their own source implementations and evidence.

A module requesting `host.residency` receives `context.Residency`. `TryGetActorPosition(out HostRegionAnchor)` supplies the captured authoritative local player position before third-person or preview camera changes. Bootstrap spawn anchors are unavailable through that getter until an actual player pose arrives. Scheduled read grants permit `TryGetCount(out uint,out ulong)` and `TryGetRegion(uint,out HostRegionResidency)`. Scheduled writes additionally permit `SetDesiredRegions(ReadOnlySpan<uint> wanted,ReadOnlySpan<uint> retained)`. Updates are atomic: out-of-range or duplicate indices and wanted regions absent from the retained set reject the entire update. Empty sets explicitly detach all regions. A successful update is applied at the next owner-thread streaming pump; publication and collision changes remain fenced.

The table15 native ABI has version1,40-byte size and a192-byte region record. Records expose source ID, bounds, phase, desired/retained flags and actual raster/collision publication flags. Generation identifies the published resident-set revision. Counts/queries return unavailable for monolithic scenes and geometry-part catalog sessions; those do not identify original source cells. Multiple payload parts belonging to one source cell must be aggregated by the game before it considers that cell attached.

CPU validation: `python tools/validation/check_tile_residency.py --out <new-directory>`. Managed native-table validation source is `tools/Source/ResidencyManagedProbe`; its private probe links the actual production interface and native projection without building the client or using a GPU.

An optional integer `tile_gpu_budget_mib` declares the world working-set admission ceiling (64 through32768MiB). Omitting it retains the caller default (normally2048MiB); the explicit `OCTARYN_CLIENT_TILE_GPU_BUDGET_MIB` override takes precedence. This accounts for allocated raster resources and conservative future ray-tracing reservations, rather than claiming all bytes are currently allocated VRAM. The separate OS-budget70% admission guard still applies. Omitted `texture_cache` uses a shared manifest namespace (`map.json.textures`): validated role/content-key matches may reuse decoded or cooked textures after upload fence completion.
