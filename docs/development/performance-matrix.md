# Matched rendering matrix

Evidence: `logs/client/performance-fixed-1440/matrix-summary.json`, generated by
`tools/validation/summarize_performance_matrix.py`. This matrix contains three
serialized runs of each variant on Windows DX12 at native 2560×1440. It uses the
bounded translation/rotation/settle/camera-cut route, fixed camera origin and
fixed presentation lighting. It is not the earlier short static-camera audit.

The summarizer verified identical camera coordinates, angles and phase at every
`ready_frame`, independent of different startup submission counts. It also
cross-checked the camera against actual CPU rendering records, the output size
against GPU records, and equality of captured sun direction/time at the same ready
frames. Each run contributes the same 348 completed frames after 120 warmup
frames and the union of all capture/readback exclusion windows.

The values below are medians of the three run-level statistics. Worst is the
maximum observed across all three runs, not the median of three worst values.

CPU frame values are elapsed frame durations including synchronization, not CPU
execution time. The machine-readable report separately retains main-thread CPU,
submission, fence-wait, lighting-pass and phase-specific distributions.

Adaptive rays reduced GPU mean by 14.0514 ms (44.6092%). The three paired
reductions were 14.0843, 14.0514 and 14.0452 ms; the larger run-mean range of either
variant was 0.03071 ms. This comfortably exceeds observed run variation.
Sparse sampling saved another 0.8313 ms (4.7644%) relative to adaptive, against a
0.02753 ms run-mean range. Its p95/p99 did not improve. Indirect and LOD variants
were approximately 0.063–0.065 ms slower than adaptive direct drawing in this
workload and do not qualify as performance-winning defaults here.

## Interpretation limits

- These are three-run observed-spread comparisons, not statistical confidence
  intervals. Image and motion acceptance remains separate.
- All 15 runs have matching executable/shader/driver/GLB/parsed-manifest identity.
  Direct captured sunlight evidence exists for the first repetition of each
  variant; the two uncaptured repetitions do not contain a direct sunlight
  sample. Cooked metadata hashes were added during the matrix and exist for only
  four of the 15 runs; the report states this coverage instead of inventing it.
- Sparse GPU mean being below 16.7 ms does not establish a 16.7 ms engine budget:
  its CPU frame mean is 16.8032 ms and GPU/CPU tail values remain about 26 ms.
  Neither the 16.7 ms nor 8.3 ms engineering milestone is fully qualified.
- These values do not qualify 4K, reconstructed modes, Vulkan, mesh shaders,
  unrestricted traversal, glass/foliage motion, or the 30-minute soak. Each needs
  its own matched evidence. No generated frames are counted.
