Octaryn API Usage

Call the shared API from a real game module.

This page is function-first. It shows how to validate a manifest, create a module instance, tick gameplay, request block edits, declare scheduled resources, and plug in authority/worldgen rules with the current octaryn-shared contracts.

Module Entry Point

The host looks for an IGameModuleRegistration, validates Manifest, then calls CreateInstance. The returned instance owns gameplay state and receives Tick calls.

using Octaryn.Shared.GameModules;
using Octaryn.Shared.Host;

namespace MyGame.Module;

public sealed class ModuleRegistration : IGameModuleRegistration
{
    public GameModuleManifest Manifest { get; } = MyManifest.Create();

    public IGameModuleInstance CreateInstance(ModuleHostContext context)
    {
        return new MyGameInstance(context);
    }
}
using Octaryn.Shared.GameModules;

public sealed class MyGameInstance : IGameModuleInstance
{
    private readonly ModuleHostContext _host;

    public MyGameInstance(ModuleHostContext host)
    {
        _host = host;
    }

    public void Tick(in ModuleFrameContext frame)
    {
        // Gameplay runs here. Use frame timing and request host commands through _host.
    }

    public void Dispose()
    {
        // Dispose module-owned ECS worlds, caches, or event buses here.
    }
}

Validate Before Loading

Use GameModuleValidator.Validate whenever tooling, tests, or host code checks a module. A valid report has no error issues.

using Octaryn.Shared.GameModules;

IGameModuleRegistration registration = new MyGame.Module.ModuleRegistration();
ModuleValidationReport report = GameModuleValidator.Validate(registration.Manifest);

if (!report.IsValid)
{
    string message = string.Join(
        Environment.NewLine,
        report.Issues.Select(issue =>
            $"{issue.Severity}: {issue.Code} - {issue.Message}"));

    throw new InvalidOperationException(message);
}

Typical validation failures are missing semantic versions, undeclared host APIs, content paths outside Data/, assets outside Assets/ or Shaders/, denied framework API groups, package IDs that are not allowlisted, and schedule writes that are not backed by the matching capability.

Host Context And Test Harness

ModuleHostContext currently exposes IModuleCommandRequests. Tests can pass a recorder so module behavior can be verified without starting the full client/server runtime.

using Octaryn.Shared.GameModules;

public sealed class RecordingCommandRequests : IModuleCommandRequests
{
    private readonly List<ModuleCommandRequest> _requests = [];

    public IReadOnlyList<ModuleCommandRequest> Requests => _requests;

    public bool TryRequest(ModuleCommandRequest request)
    {
        _requests.Add(request);
        return true;
    }
}

var commands = new RecordingCommandRequests();
var host = new ModuleHostContext(commands);
using var instance = new MyGameInstance(host);

instance.Tick(new ModuleFrameContext(deltaSeconds: 1.0 / 60.0, frameIndex: 1));

bool requestedEdit = commands.Requests.Any(request =>
    request.Kind == ModuleCommandRequestKind.SetBlock);

Use Frame And World Time

ModuleFrameContext gives the module frame delta, frame index, and server-owned world time. Use it for gameplay clocks and deterministic periodic work.

using Octaryn.Shared.GameModules;
using Octaryn.Shared.Time;

public void Tick(in ModuleFrameContext frame)
{
    double dt = frame.DeltaSeconds;
    ulong frameIndex = frame.FrameIndex;
    WorldTime time = frame.WorldTime;

    bool everyHalfSecond = ((ulong)(time.TotalSeconds * 2.0) % 2UL) == 0;
    bool everySixFrames = frameIndex % 6UL == 0UL;

    if (everyHalfSecond && everySixFrames)
    {
        RunPeriodicGameplay(dt, time.DayIndex);
    }
}

Construct a real world-time frame in tests when gameplay depends on time:

var worldTime = new WorldTime(
    TickId: 120,
    DayIndex: 3,
    DeltaSeconds: 1.0 / 60.0,
    TotalSeconds: 300.0);

var frame = new ModuleFrameContext(1.0 / 60.0, 120, worldTime);

Request Block Edits

Modules do not directly mutate server storage. They request commands; server authority validates and applies them.

using Octaryn.Shared.GameModules;
using Octaryn.Shared.World;

public void PlaceBlock(BlockPosition position, BlockId block)
{
    var edit = new BlockEdit(position, block);
    var request = ModuleCommandRequest.SetBlock(edit, requestId: 42);

    bool acceptedByQueue = _host.Commands.TryRequest(request);
    if (!acceptedByQueue)
    {
        // Queue is full or command writes are not open for this scheduled work.
    }
}

public void BreakBlock(BlockPosition position)
{
    var request = ModuleCommandRequest.BreakBlock(position, requestId: 43);
    _host.Commands.TryRequest(request);
}

For block edits to validate, the module manifest must request ModuleCapabilityIds.WorldBlockEdits, request HostApiIds.Commands, and declare a scheduled write to HostApiIds.Commands.

Declare Scheduled Access

A scheduled system declares where it runs, what host resources it reads, and what host resources it writes. Command writes must be explicit.

using Octaryn.Shared.Host;

public static class MySchedule
{
    public static readonly ScheduledSystemDeclaration FrameTick = new(
        SystemId: "mygame.frame_tick",
        Phase: HostWorkPhase.Gameplay,
        FrameOrTickOwner: HostScheduleIds.FrameOrTickOwner,
        Reads:
        [
            new ScheduledResourceAccess(HostApiIds.Frame, ScheduledAccessMode.Read)
        ],
        Writes:
        [
            new ScheduledResourceAccess(HostApiIds.Commands, ScheduledAccessMode.Write)
        ],
        RunsAfter: [],
        RunsBefore: [],
        Flags: HostWorkScheduleFlags.DeterministicOrder |
            HostWorkScheduleFlags.RequiresTickBarrier,
        CommitBarrier: HostScheduleIds.FrameOrTickEndBarrier);
}
Schedule: new GameModuleScheduleDeclaration(
[
    MySchedule.FrameTick
])

If a system writes host.commands without requesting HostApiIds.Commands and ModuleCapabilityIds.WorldBlockEdits, validation rejects the module.

Implement Block Authority Rules

Modules that provide authoritative block rules implement IBlockAuthorityRulesProvider. The server calls these functions while validating edits and block stability.

using Octaryn.Shared.GameModules;
using Octaryn.Shared.World;

public sealed class ModuleRegistration :
    IGameModuleRegistration,
    IBlockAuthorityRulesProvider
{
    public IBlockAuthorityRules BlockAuthorityRules { get; } = new MyBlockRules();

    // Manifest and CreateInstance omitted.
}
using Octaryn.Shared.World;

public sealed class MyBlockRules : IBlockAuthorityRules
{
    private static readonly BlockId Stone = new(1);
    private static readonly BlockId Dirt = new(2);

    public bool IsKnownBlock(BlockId block)
    {
        return block == BlockId.Air || block == Stone || block == Dirt;
    }

    public bool CanApplyEdit(BlockEdit edit, BlockId previousBlock)
    {
        return IsKnownBlock(edit.Block) && edit.Block != previousBlock;
    }

    public bool CanStaySupported(BlockId block, BlockId blockBelow)
    {
        return block == BlockId.Air || blockBelow != BlockId.Air;
    }

    public bool IsClientPlaceable(BlockId block)
    {
        return block == Stone || block == Dirt;
    }

    public bool IsSolidBlock(BlockId block)
    {
        return block == Stone || block == Dirt;
    }
}

Host-side edit validation uses these rules before it persists or replicates the changed block.

Implement World Generation Rules

World-generation providers supply material choices, water level, terrain-column plans, and feature edits. The server owns terrain storage; the module supplies rules.

using Octaryn.Shared.GameModules;
using Octaryn.Shared.World;

public sealed class ModuleRegistration :
    IGameModuleRegistration,
    IWorldGenerationRulesProvider
{
    public IWorldGenerationRules WorldGenerationRules { get; } = new MyWorldgenRules();

    // Manifest and CreateInstance omitted.
}
using Octaryn.Shared.World;

public sealed class MyWorldgenRules : IWorldGenerationRules
{
    private static readonly BlockId Water = new(5);
    private static readonly BlockId Sand = new(6);
    private static readonly BlockId Grass = new(7);
    private static readonly BlockId Dirt = new(8);
    private static readonly BlockId Stone = new(9);
    private static readonly BlockId Snow = new(10);
    private static readonly BlockId Flower = new(11);

    public int WaterHeight => 62;

    public BlockId WaterBlock => Water;

    public TerrainMaterialRules Materials => new(Sand, Grass, Dirt, Stone, Snow);

    public TerrainColumnPlan PlanTerrainColumn(TerrainColumnSample sample)
    {
        int terrainHeight = 48 + (int)(sample.HeightNoise * 32.0f);
        bool lowland = sample.LowlandNoise < 0.35f;
        BlockId surface = lowland ? Sand : Grass;

        return new TerrainColumnPlan(
            sample.WorldX,
            sample.WorldZ,
            sample.LocalX,
            sample.LocalZ,
            sample.LocalWidth,
            sample.LocalDepth,
            terrainHeight,
            DecorationY: terrainHeight + 1,
            SurfaceBlock: surface,
            FillBlock: Dirt,
            IsLowland: lowland,
            HasGrassSurface: surface == Grass);
    }

    public void AddFeatureBlocks(
        TerrainColumnPlan column,
        float featureNoise,
        ICollection<BlockEdit> edits)
    {
        if (column.HasGrassSurface && featureNoise > 0.92f)
        {
            edits.Add(new BlockEdit(
                new BlockPosition(column.WorldX, column.DecorationY, column.WorldZ),
                Flower));
        }
    }
}

Declare Content, Assets, Packages, And Dependencies

Manifest declarations are exact. IDs must be owned by the module ID prefix, and paths must stay inside the allowed module folders.

new GameModuleDependency(
    ModuleId: "octaryn.basegame",
    MinimumVersion: "0.1.0",
    MaximumVersion: "0.1.0",
    IsRequired: true);

new GameModuleContentDeclaration(
    ContentId: "mygame.blocks",
    ContentKind: "block",
    RelativePath: "Data/Blocks/mygame.blocks.json");

new GameModuleAssetDeclaration(
    AssetId: "mygame.texture.atlas.color",
    AssetKind: "atlas",
    RelativePath: "Assets/Atlases/mygame-color.png");

Allowed content kinds currently include block, item, material, recipe, tag, loot_table, feature, biome, and rule. Allowed asset kinds currently include atlas, blockstate, model, shader, texture, ui, and audio.

Loader Convention

The bundled loader convention expects the module registration type under the module assembly namespace plus .Module.ModuleRegistration. Keep the project, namespace, and folder layout aligned.

namespace MyGame.Module;

public sealed class ModuleRegistration : IGameModuleRegistration
{
    // Host-discoverable registration type.
}

A clean module layout keeps source, data, assets, and tools separate:

mygame/
  Source/Managed/Module/ModuleRegistration.cs
  Source/Managed/Game/MyGameInstance.cs
  Source/Managed/Rules/MyBlockRules.cs
  Source/Managed/Rules/MyWorldgenRules.cs
  Data/Blocks/mygame.blocks.json
  Data/Rules/mygame.terrain.json
  Assets/Atlases/mygame-color.png
  Tools/
